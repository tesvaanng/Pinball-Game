# 決策記錄（Decision Log）

> **用途**：記錄每個設計決策的**理由**，以及**被推翻的方案與原因**。
> **讀者**：想了解設計意圖、或想重新評估某個決定的人或 AI。
> **與 `Design.md` 的關係**：`Design.md` 是「現在是什麼」，本文件是「為什麼是這樣、以及為什麼不是別的」。

---

## 使用方式

| 你想做什麼 | 去哪裡 |
|---|---|
| 知道遊戲現在怎麼設計 | `Design.md` |
| 知道某個決定為什麼這樣定 | 本文件第二部分 |
| **想提議一個新方案** | **先看第三部分「已推翻的決定」**——很可能已經討論過了 |
| 知道哪些原則是在討論中學到的 | 本文件第四部分 |

**給 AI 的提示**：第三部分是為了防止重複討論。若你要提議的方案在第三部分裡，請先說明**這次的新理由與上次被推翻的理由有何不同**，否則不應該重新提議。

# 第二部分：關鍵決策的理由

## 2.1 為什麼是「力度條」而不是「拖曳瞄準」

**曾一度採用 Peglin 式拖曳瞄準（發射器在頂部，拖曳決定方向），後來改回力度條。**

理由：

| # | 理由 |
|---|---|
| 1 | **讀法乙的節奏需求**：充能條週期性滿格需要球在盤面上待得夠久；瞄準＝靜態規劃，球飛時沒事做；力度＋（日後的）主動技能＝球飛時仍可介入 |
| 2 | **可學習性更適合灰盒驗證**：「力度↔進場層」的對應，比「瞄準↔落點」更容易用統計驗證（看玩家會不會自己說出「37% 走左漏斗」） |
| 3 | **懸念保留**：瞄準的預測線會洩漏太多（能預覽牆壁反彈＝能算出進哪個袋），懸念消失；力度只能控制「從哪一層進場」，進場後的混沌保留 |
| 4 | 與既有設計（柏青哥式右側軌道、進場層、幽靈試投、落點熱區）相容，不需重寫 |

> ⚠️ **被移除的理由**：原本還有一條「T1–T11 已建好，改瞄準要重寫文件，成本高」。
> **這是沉沒成本論證，不是設計理由，已刪除。** 當時所有設計都只是 markdown 文字，沒有任何一行程式碼——改文件的成本是幾分鐘，改已實作的東西才是幾週。**用「文件要重寫」來鎖住輸入方式，等於用最便宜的成本去換最貴的決定。**

## 2.2 為什麼「基礎玩法 ＝ 肉鴉最底層循環」（讀法乙），而不是「純彈珠」

**這是本專案最重要的方向修正。**

| | 讀法甲（純彈珠） | **讀法乙（採用）** |
|---|---|---|
| 基礎玩法 | 投球 → 得分 → 球進袋。無敵人、無傷害、無充能 | **投球 → 賺分 → 充能 → 自動開火 → 傷害 → 敵人 HP，只是數值極小** |
| 風險 | 把「純彈珠」調到好玩，很可能調出一個**靠混沌與運氣取勝**的盤面。這種盤面接上肉鴉後會壞掉——肉鴉需要「玩家的選擇有可預測的後果」，否則 build 無法被評估 | — |

**讀法乙從第一天就要求「輸入 → 路線 → 袋口 → 分數 → 傷害」這條因果鏈是可學習的。** 這條鏈一旦成立，純彈珠的部分自然就好玩；而且它直接就是肉鴉的地基。

**判斷標準**：把第 1 層單獨抽出來，它是不是一個完整的小遊戲？如果是，基礎玩法就對了。

## 2.3 為什麼「核心機制 vs 輔助機制」的區分很重要

**舊原則**（絕對）：機制要完整，數值要微小。肉鴉構築不引入新機制，只提供放大既有機制的槓桿。

**新原則**（修正後）：

> **核心機制要完整，數值要微小。輔助機制可以是解鎖項，因為它們不參與核心循環，所以不會造成空轉。**

| 類別 | 定義 | 能不能當解鎖項 | 例子 |
|---|---|---|---|
| 核心機制 | 拿掉它，遊戲不成立 | ❌ 不行 | 力度、球上分數、充能條、逐發開火、傷害、怪物 |
| 輔助機制 | 拿掉它，核心循環照樣成立 | ✅ 可以 | 主動技能、多球／連發、當選模式 |

**解鎖的合法性條件**：

> **被解鎖的東西，不能是「已經在累積卻不生效的資源」。**

- ❌ 壞的解鎖：前期分數沒用，拿到遺物才有用 → 前三層空轉，玩家覺得被騙
- ✅ 好的解鎖：前期沒有技能，拿到技能後多一個決策維度 → 純粹的獲得

**「解鎖」本身不是問題，「解鎖一個已經在累積卻不生效的東西」才是問題。**

## 2.4 為什麼「怪物在盤面之外」

**曾在 `Roguelike-Plan` 18.7 推薦「方案 C：敵人在盤面上，但碰撞幾何永不改變」，後來改為「盤面之外」。**

理由：

| # | 理由 |
|---|---|
| 1 | **盤面幾何全程不變** → 球的落點分布穩定 → 盤面設計完全可控、可驗證 |
| 2 | **架構乾淨**：球 → 分數 → 充能 → 開火 → 怪物，鏈條單一。球永遠只做「賺分」一件事 |
| 3 | 與「開火發生在落袋結算後」的決定一致（見 2.5），開火是純粹的「充能條 → 怪物」 |

**代價**：失去物理連結（球不會碰到怪物）。用「開火演出」補償。

## 2.5 為什麼「開火發生在落袋結算之後」

**曾在 `Roguelike-Plan` 17.3 設計過「充能條在飛行中即時累積、滿了就開火」，後來改為「落袋結算後才充能」。**

理由：

| # | 理由 |
|---|---|
| 1 | 接上了原本斷掉的管線：`球上分數 × 袋口倍率` 的結果有了明確去向（→ 充能條） |
| 2 | 讓「袋口佈局」直接影響戰鬥（落錯袋 → 充能少 → 傷害少），二階張力變成戰鬥層面的，不只是分數層面 |
| 3 | **懸念更強**：球快落袋時玩家希望它再彈一下，因為每多彈一下就多一分機會讓充能條滿 |
| 4 | 節奏更清楚：一顆球 ＝ 一次「累積 → 結算 → 可能爆發」 |

**已作廢的相關設計**：`Roguelike-Plan` 17.4.3「充能上限必須與單球平均分數同曲線」——理由已由 2.6 取代。

## 2.6 傷害模型的演變：從「充能上限 × 轉換率」到「固定開火傷害」

**這是本設計最重要的一次簡化。**

### 舊模型（已棄用）

```
每次開火傷害 = 充能上限 × 轉換率
每球總傷害   = (結算分數 / 充能上限) × (充能上限 × 轉換率)
             = 結算分數 × 轉換率        ← 充能上限消失了
```

**問題**：充能上限只是「切成幾刀」，沒有機械重量。玩家在它身上做 build 沒有意義。

### 新模型（現行）

```
每次開火傷害 D = 固定常數（與充能上限無關）
開火次數       = 結算分數 / 充能上限 C
每球總傷害     = (結算分數 / C) × D
```

**好處**：

| # | 好處 |
|---|---|
| 1 | 公式更簡單——**「轉換率」這個名詞消失**，換成玩家一眼就懂的「每次開火傷害」 |
| 2 | **三個槓桿都直接影響總傷害**：結算分數 ↑、開火傷害 `D` ↑、充能上限 `C` ↓。build 深度增加 |
| 3 | 每個槓桿的**玩家感受不同**：「分數跳更快」／「數字變大了」／「噠噠噠噠噠」 |

**代價**：

| # | 代價 |
|---|---|
| 1 | **三重乘法**（`結算分數 × D / C`）比雙指數更難平衡 → 這是本設計最大的數值風險 |
| 2 | `C` 同時是「設計者的節奏旋鈕」與「玩家的傷害槓桿」，身份衝突（見 `Design.md` 6.4） |
| 3 | **「提高 `C`」變成純粹的壞選擇**（傷害變少、頻率變低）——它不再是玩家的 build 方向，只是設計者的旋鈕 |

**衍生設計（為了讓三個軸互相取捨）**：

因為三個軸數學上都是「乘傷害」，必須靠**敵人機制**製造情境差異，否則玩家只會選數字最大的：

| 機制 | 獎勵哪個軸 | 為什麼 |
|---|---|---|
| **固定值護甲**（非百分比） | **提高 `D`** | 小單發被吃掉大比例、大單發被吃掉小比例 |
| **適應裝甲**（受擊遞減） | **提高 `C`** | 懲罰攻擊次數 |
| **易傷疊層**（連續命中疊層） | **調低 `C`** | 獎勵攻擊次數 |

> ⚠️ **護甲必須改成「固定值減免」。** 舊設計的「百分比減免 ＋ 10% 下限」對所有大小的傷害一視同仁，**不產生任何取捨**。
> 新設計：`實際傷害 = max(傷害 − 護甲, 傷害 × 0.10)`。10% 下限仍然必需（避免「完全打不動」的死局）。

**設計者要控制的兩個曲線（暫定）**：

| 要控制的東西 | 該動的數字 |
|---|---|
| 開火節奏（不要爆走） | 充能上限 `C ∝ 單球結算分數` |
| 難度 | 怪物 HP `∝ 目標每球傷害` |

## 2.7 為什麼用「固定值護甲」而不是「硬護甲門檻」或「百分比減免」

**曾設計「傷害 < 護甲 → 0 傷害」（硬門檻）→ 已否決。**
**也曾設計「百分比減免 ＋ 10% 下限」→ 已淘汰（見下方）。**

### 硬門檻被否決的理由

| # | 理由 |
|---|---|
| 1 | **指數成長會讓玩家在拿到某個升級的瞬間，從「完全打不動」跳到「直接輾過」**，中間沒有過渡帶，極難平衡 |
| 2 | **它讓「完美構築可以一定程度強打」在數學上不可能**——低於門檻就是 0，沒有「一定程度」 |

### 百分比減免被淘汰的理由

**它對所有大小的傷害一視同仁 → 不產生任何取捨。** 提高 `D`（大單發）與調低 `C`（多次小攻擊）被懲罰的比例完全一樣，敵人機制就失去了「讓不同 build 有不同價值」的功能。

### 現行：固定值減免

```
實際傷害 = max(傷害 − 護甲, 傷害 × 0.10)
```

- **固定值減免**：小單發被吃掉大比例、大單發被吃掉小比例 → **獎勵「提高 `D`」**
- **10% 下限**：仍然必需，它是「完美構築可以一定程度強打」能否成立的唯一保證
- 例：護甲 30：40 傷 → 10 傷（25% 有效）；200 傷 → 170 傷（85% 有效）

**另外兩個搭配機制**：適應裝甲（受擊遞減 → 獎勵提高 `C`）、易傷疊層（連續命中疊層 → 獎勵調低 `C`）。三者合起來讓三個傷害軸各有場合。

## 2.8 為什麼「球上分數 × 袋口倍率」的顯示要那樣子（飄字規格）

因為 **球飛行時玩家完全不能做事**（2.1.2），飄字是玩家唯一的參與機制。

| 規則 | 理由 |
|---|---|
| 跟著球跑 | 讓玩家知道「這顆球現在值多少」 |
| 後續加分累加到同一數字 | 數字持續長大 ＝ 微型的大數字爽感 |
| 閒置後隱藏，但分數仍累積 | 讓畫面有呼吸；但分數不能歸零，否則玩家會覺得被騙 |

**⚠️ 這是全專案優先度最高的表現層工作，M0 就要做好，不能留到最後。**

## 2.9 為什麼「超時以 1 倍結算」

**曾設計「三段式卡球救援」（1.5 秒小推／3 秒大推／5 秒判定結束），已由本規則取代。**

| 理由 |
|---|
| 一條規則同時處理三種狀況：卡球、球無限彈跳、超時 |
| 不嚴厲——分數保留，只是失去袋口倍率 |
| **天然獎勵短球**，抑制長球帶來的問題，與「無干預」互補 |

## 2.10 為什麼「盤面必須有結構」（5–10% 面積）

**關鍵洞察**：

> **均勻的 Plinko 釘子網格，會讓「力度」完全失去意義。**

Plinko 網格的設計目的就是**消除輸入的影響**——不管從哪裡丟，結果都是同一條常態分布。這是 Plinko 作為賭博遊戲的特性。

柏青哥式力度的意義正好相反：**讓玩家控制從哪一層進場**。兩者直接衝突。

**解法**：保留 Plinko 的視覺與手感，但加入少量結構元素（分區擋板、漏斗、密度差異），**結構只佔 5–10% 面積**。
**90% 看起來還是 Plinko，但那 10% 決定遊戲有沒有技術成分。**

**已識別的子陷阱**：若「空曠區」直通高倍率袋口，它就變成必勝路線，取捨消失。
→ **原則：「空曠」的代價必須是「不可控」，不是「又快又好」。**

## 2.11 工程決策的理由（摘要）

| 決策 | 理由 |
|---|---|
| **用 2D 物理模擬** | 彈珠台 3D 物理是出了名的 jank（穿模、卡死、不可重現），與「大量球＋可驗證平衡」直接衝突。0.5 秒的彈跳預測、盤面驗證器都建立在 2D 上 |
| **BigNumber 第一天就用** | 晚改要動幾百處型別。成本約 200 行、半天 |
| **機率／百分比用 `double` 而非 `BigNumber`** | 「10%」這種小數用 `BigNumber`（mantissa ≥ 1）無法表示 |
| **自寫決定性 RNG** | `UnityEngine.Random` 是全域狀態、無法分叉、無法存檔回復 |
| **不用操作日誌式存檔** | 物理不可複現，日誌式重播在物理遊戲裡行不通 |
| **asmdef／純 C# 分層可延後** | 唯一真正的理由是「跑 headless 模擬調平衡」，那是 M3 的事。現在只需「資料夾 ＋ 一個習慣」 |
| **觸發佇列步數上限** | 「A 觸發 B，B 觸發 A」在長專案裡一定會發生，而且通常發生在玩家 build 成形的爽點上——當掉最傷 |

## 2.12 為什麼充能條是「連續累加器」（溢出無損、逐發開火）

**這是 v1.1 補完的核心模型。** v1.0 只寫了「滿了就開火並扣除一個上限」，**沒有說明溢出怎麼辦**——那時預設每球結算後充能條歸零，等於「差一點就滿」的部分會被浪費。

### 現行模型

```
充能條 += 結算分數          ← 溢出無損，直接推進到下一條
while 充能條 >= C:
    充能條 -= C
    開火一次
```

**理由：**

| # | 理由 |
|---|---|
| 1 | **「差一點就滿」不該被懲罰**。歸零制的話，玩家會學會「湊剛好」，那是一種算術作業，不是樂趣 |
| 2 | **爆走感變成基礎玩法自帶的**。一顆爆分球可以一瞬間連開數次、連續清空怪物——不需要任何肉鴉遺物 |
| 3 | **期待與 payoff 分家**。落袋 ＝ 期待（未知 × 倍率）；充能爆開 ＝ payoff（唰唰唰打 N 下）。v1.0 讓「落袋」同時扛期待和 payoff，兩個都不夠強 |
| 4 | 它讓「層間保留」（2.13）在邏輯上自然成立——既然條是連續的，跨球跨層就是同一條規則 |

### 開火呈現：逐發、可數

**每滿一條 `C` → 一顆子彈從充能條射出，充能條演出「充滿 → 歸零 → 充滿 → 歸零」，間隔約 0.15 秒。**

| 為什麼不是「一次爆發」 |
|---|
| 特殊怪物有「每受擊 N 次觸發反擊」這類機制（`Design.md` 3.3.4）。一次性爆發的話，玩家無法把「打了幾下」和敵人的反應對應起來，機制就讀不出來 |

> **「同時爆發／光柱」保留給肉鴉層的多發流派**——它從「基礎玩法的規則」變成「高頻流的視覺獎勵」，兩邊都得到好處。

### 開火次數沒有硬上限

用**特效分級**（1–3 次逐發／4–10 次加速逐發／10 次以上聚合演出）避免畫面失控，但**傷害結算仍然逐發**。

⚠️ 這讓「`C` 固定而分數指數成長」的後期會產生數百次開火。**決定：M0 先用固定 `C` 驗證手感，平衡階段再處理**（`Design.md` 6.4）。

## 2.13 為什麼「層間充能保留」與「防鞭屍」是同一條設計

原始設計隱含「怪物死 → 本層結束 → 下一層重置」。改成：

1. 怪物死亡 → **立即停止開火**（防鞭屍）
2. 未發射的能量（含整條滿管）**全部保留到下一層**
3. 本層的球**全部落袋後**才結束
4. **例外：下一層是 Boss 房 → 充能清空**

**理由：**

| # | 理由 |
|---|---|
| 1 | **溢傷不該被丟棄**。如果剩下的十幾發打在一具屍體上，那是浪費也是荒謬；如果直接消失，玩家會覺得「太強反而被懲罰」 |
| 2 | **它創造了一個新的目標**：「這一波能不能連穿兩間？」——這是基礎玩法裡少數主動產生爆走感的規則 |
| 3 | **已經在飛的球不該被憑空取消**。球是玩家剛剛做的決策，中途沒收等於否定那個決策 |
| 4 | **Boss 房必須是乾淨的戰鬥**，否則前面囤積的能量可以直接跳過 Boss——那會讓 Boss 設計全部失效 |

> ⚠️ **副作用（已知風險）**：怪物 HP 太低時，一顆爆分球就能連穿三層。**怪物 HP 曲線必須能吃下囤積的爆發**，這是難度曲線的主控點。

## 2.14 為什麼失敗條件是「玩家 HP 歸零」而不是「回合用完」

**這是基礎玩法最後一塊補完的拼圖。**

原本的設計是：每層 8–10 顆球，**球用完怪物還活著 → 本局結束**（純 DPS 檢定）。
但當「怪物會在球打完後攻擊」被定下來之後，這句話就出現了矛盾：**如果球用完就已經輸了，那怪物攻擊是做什麼的？**

### 三個候選

| 方案 | 規則 | 評價 |
|---|---|---|
| **A. 攻擊純表演** | 失敗仍看球數 | ❌ 攻擊沒有後果，不如不做 |
| **B. 玩家有 HP，無回合上限** ⭐ | 8–10 顆球 ＝ **一輪**；球打完 → 怪物攻擊扣玩家 HP → **補滿球數再來一輪**，直到一方死亡 | ✅ **採用** |
| **C. 兩種輸法並存** | 球用完怪物還活 → 輸；玩家 HP 歸零 → 也輸 | ❌ 兩條規則搶同一件事，互相打架 |

### 為什麼選 B

| # | 理由 |
|---|---|
| 1 | 它**完全符合「球打完就攻擊」**——攻擊變成回合的節拍器，而不是裝飾 |
| 2 | 一層變成一場**消耗戰**：玩家 HP 是燒著的爐子，怪物 HP 是你要打穿的牆 |
| 3 | **資源焦慮有地方落腳**：不再是「我還剩幾顆球」，而是「我還剩 30 HP，牠還有 500，這輪打不夠我就死」 |
| 4 | 玩家 HP 順便成為肉鴉層的新 build 軸（回血、減傷、吸血），而且**不干預核心循環** → 是合法的輔助機制（2.3） |
| 5 | 它**解放了「球數」**：8–10 顆從「一層的總量」變成「一輪的量」，於是球數變成**可以隨樓層調整的節奏旋鈕**，不需要動 `C` |

### 推翻了什麼

| 被推翻 | 原因 |
|---|---|
| **「回合用完怪物仍存活 → 本局結束」**（v1.1 以前） | 與「怪物會攻擊」直接矛盾。改為只保留「玩家 HP ≤ 0」 |
| **「球數 ＝ 一層的總資源」** | 改為「球數 ＝ 一輪的資源，會補滿」。資源焦慮改由玩家 HP 承擔 |

> **⚠️ 尚未解決的副作用**：如果玩家的 DPS 趨近 0（例如一直打不到釘子），會變成「每輪被打一次、永遠打不死」的慢速死亡。
> 這在設計上是可接受的（它會終結，只是難看），但**需要一個防呆**（附錄 A.1 的「最大輪數」），以免模擬無限迴圈。

# 第四部分：討論過程中確立的原則

這些是跨決策的通則，未來遇到新問題時可以拿來當篩子。

| # | 原則 | 出處 |
|---|---|---|
| 1 | **機制要完整，數值要微小**（核心機制）；輔助機制可解鎖 | 2.2 / 2.3 |
| 2 | **解鎖的合法性**：不能解鎖「已經在累積卻不生效的資源」 | 2.3 |
| 3 | **「有趣」不是來自機制數量，是來自決策密度**。每一次操作要有 2–3 個可以算的後果 | 前期設計 |
| 4 | **門檻型數值在指數成長的遊戲裡很危險**（會瞬間從不可能變輾壓）。用連續型機制取代 | 2.7 |
| 5 | **單調遞增的獎勵會讓決策退化**（永遠選極端）。決策需要「等待的成本」或「邊際遞減」 | 3.2 的 #2 |
| 6 | **均勻的隨機場會消除輸入的意義**。要讓玩家控制結果，盤面就必須有結構 | 2.10 |
| 7 | **「空曠」的代價必須是「不可控」，不是「又快又好」** | 2.10 |
| 8 | **玩家的參與感必須有來源**。若操作被移除，就要有別的東西（例如看著數字長大）補上，而且它會變成最高優先度的工作 | 2.8 |
| 9 | **不要用沉沒成本當設計理由**。文件便宜、程式貴——用便宜的東西鎖住貴的決定是錯的 | 2.1 |
| 10 | **同一個機制換個位置可以從 bug 變成 feature**（例：一個原本導致決策退化的獎勵機制，換個位置後變成平衡兩個 build 的砝碼） | 3.2.1 |
| 11 | **平衡目標不是「兩個流派一樣強」，而是「在不同情境下各有價值」**。這比調數值容易得多 | 3.3 |
| 12 | **能用手玩驗證的事就不要用討論決定；能用模擬驗證的事就不要用手玩** | 開發流程 |
| 13 | **「引擎」比「放大器」更能產生爆走感**。把一個系統的輸出接到另一個系統的輸入（傷害→充能、開火→盤面、分數→當選），比單純把數字乘大更能讓玩家「停不下來」——放大器的效果在第三層就被習慣了 | 3.9 |
| 14 | **「溢傷被丟棄」是一種隱形的懲罰**。玩家變強之後反而更容易浪費，會產生「太強反而被懲罰」的荒謬感。溢傷要嘛保留、要嘛轉移，不要消失 | 2.13 |
| 15 | **不可複現的系統與必須可複現的系統要切開**。物理不可複現是事實，但規則必須可複現——否則平衡模擬、存檔、每日挑戰、bug 重現全部做不到。**規則層不得依賴引擎** | 附錄 B.1 |
| 16 | **「結算」與「演出」必須分開**。規則一次算完，演出照著結果播。綁在一起的話，加速、跳過、存檔全部會壞 | 附錄 B.3 |
